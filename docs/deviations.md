# Deviations from the design and build brief

Codex owns continuation, review and the authorized merge as of 2026-11-27; see [AGENTS.md](../AGENTS.md) and the [historical handover](CLAUDE_CODE_HANDOVER.md). Final implementation `1cceb73` passed 33 Node tests, 19 Playwright tests, lint, ABAP parsing and Linux MTA packaging in [CI run 42857157309](https://github.com/amahesh83/jones-vendor-onboarding/actions/runs/42857157309). New privacy/security fixes are being verified against this baseline. Implementation/source closure below does not imply live SAP/BTP validation.

| # | Brief said | Built | Why |
|---|---|---|---|
| D1 | SAPUI5 vendor portal + Fiori elements internal app | Custom HTML/CSS/JS for both ([ADR-002](decisions/ADR-002-custom-web-ui.md)) | Owner asked for a fun, beautiful, not-bland UI |
| D2 | Object Store for documents | Documents stored in the database (`LargeBinary`) | Kept, reviewed 2026-11-10: low volume (tens per month; uploads are limited by type and size in `files.js`); one less BTP service. Swap later behind `srv/lib/files.js` |
| D3 | CAP persistent outbox for SAP calls | **Reliability gap closed:** transactional `SapCreationJobs` application outbox with conditional claims, persisted attempts/backoff, five-minute leases, startup recovery and terminal `SAP_ERROR` | Uses a small application outbox instead of CAP's generic dispatcher to preserve existing creation logic and avoid holding a SQLite transaction across remote calls. Separate-process recovery and rollback tests pass; ECC idempotency still needs DEV verification. See [runtime reliability](runtime-reliability.md) |
| D4 | Mail adapters local / graph / smtp | local and graph only | Kept, reviewed 2026-11-10: Graph is the expected Jones route (Q14). The local adapter refuses production, so a BTP deployment needs `VOB_GRAPH` before vendors can receive links |
| D5 | `@cap-js/audit-logging` | **Implementation closed:** plugin pinned, vendor data-subject annotations, explicit `SensitiveDataRead` for unmasked bank reads on custom routes, production Audit Log binding in MTA | Local plugin invocation tested. Provision the existing write-capable `vob-audit-log` service and verify delivery in BTP before go-live |
| D6 | Playwright E2E (13 scenarios) + axe | **Implemented:** original 13 journeys plus demo-fill and configurable-route journeys; axe gates and screenshot/overflow checks at 375/1280 px in light/dark | Runs against `npm run demo`. Email-preview iframe remains sandboxed; its content cannot run axe, so the mailbox shell is scanned and the preview title checked. See [test evidence](test-evidence/README.md) for actual results and limits |
| D7 | ABAP in full abapGit format with ABAP Unit | **Packaging/source gap closed:** offline abapGit export, package/class/interface/table XML, six ABAP Unit source cases including a duplicate-store double; IBAN lookup and GOS implementation replace stubs; request-log written before vendor commit | Archive-integrity and parser checks pass. ABAP Unit has NOT been run in SAP. Semantic compilation, API names, locking, number assignment, WHT mapping and live GOS remain mandatory `VERIFY IN DEV` items; see [ABAP install](abap-install.md) |
| D8 | Rate limits | In-memory per instance: coarse socket-peer limit plus SHA-256 keyed invite-token limits; `X-Forwarded-For` is ignored until the QAS App Router→CAP chain is verified | Kept, reviewed 2026-11-27: the socket peer can be shared behind Cloud Foundry ingress, so the coarse cap is deliberately high and token-specific buckets are the primary OTP/invite guard. Valid only while `vob-srv` runs as **one instance** (the MTA has no `instances` setting, so CF uses 1). Before scaling out, move limits to a shared store. Verify the real forwarding chain before using forwarded client addresses |
| D9 | Reminder job lease in the DB | Interval timer per instance (`cds.requires.vob.jobMinutes`) | Kept, reviewed 2026-11-10: single instance only. Two instances would send duplicate reminders. SAP creation itself is safe with several instances (D3 claims jobs conditionally) |
| D10 | Seed configuration from `db/data` CSVs | Admin-editable configuration (Settings, ApprovalRoutes, PaymentTerms, AccountTypes, DocumentTypes, CompanyCodes, RoleDirectory) is seeded by the app at start-up from `srv/seed/`: missing setting names are added, and other tables only when empty. RoleDirectory is never seeded in production | Added 2026-11-10. CAP turns `db/data` CSVs into HDI `.hdbtabledata`, and HDI rewrites that content on every deployment, which would silently undo admin route and setting changes and load the `@jones.test` placeholder approvers into production. Verified: `gen/db` now only contains table data for Countries, Currencies and WithholdingCodes; a Node test proves admin values survive re-seeding. Not yet verified on a real HDI redeploy |
